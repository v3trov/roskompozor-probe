# Roskompozor Probe 2.0

Общий движок для Linux и OpenWrt 24.10, Python 3.9+, стандартная библиотека.
Установка: `install.sh` в корне репозитория Probe. Служба:
`roskompozor-probe-next`, конфигурация `/etc/roskompozor-probe-next/config.json`.
При обновлении ключ сохраняется, резервная копия создаётся до замены программы.

## Измерения

- Обычные DNS, ping, TCP, TLS, HTTP/HTTPS с проверкой сертификата и редиректов.
- DNS A/AAAA по UDP, TCP, DoT и DoH у Cloudflare и Google.
- Отдельные IPv4/IPv6 TCP 80/443, TLS-handshake и проверка сертификата.
- Собственные контрольные точки: baseline / проверяемый SNI / baseline;
  фиксированные 64 КиБ данных. Тела проверяемых сайтов не сохраняются.
- Недоступный контроль не является основанием для вывода о фильтрации SNI.
  Различия DNS, в том числе адресов CDN, сохраняются как наблюдения.

Контрольный HTTP Host фиксирован; между попытками меняется TLS SNI.
Точки задаются администратором в `controls`. Контрольные точки отдают только фиксированные данные, с ограничением частоты
и соединений; новый узел не требует ручного изменения IP allowlist.
Тестовые тела не передаются пользовательским целям.

Дополнительные измерения находятся в поле `experimental` с `version: 2.0.1`.
Публичные выводы о работе реального сайта используют обычные измерения;
успех контрольного сервера не объявляет сайт доступным.

## Задания и очередь

HTTPS GET `/api/probe/checks?limit=1` или `limit=2`, POST `/api/probe/results`.
Сервер и проверка TLS API фиксированы: `https://roskompozor.ru`.
Редиректы API и proxy из окружения запрещены. Задания сохраняются до измерения,
отчёты — до POST; повторная отправка после сбоя и перезапуска идемпотентна.
Готовый отчёт не ждёт остальных заданий пачки. SQLite расположен в
`/var/lib/roskompozor-probe-next/api/queue.sqlite`; на OpenWrt —
`/etc/roskompozor-probe-next/state/queue.sqlite`, сохраняется при перезагрузке.

Отклонённые отчёты сохраняются для разбора. Завершённая история ограничена
500 отчётами / семью днями; неотправленные отчёты очистка не удаляет.
Измерение ограничено 65 секундами с завершением группы дочерних процессов.

## OpenWrt и ZeroBlock

Установщик добавляет Python и обновляет установленный интерфейс LuCI.
OpenWrt запускает Probe от root, как прежний native-клиент: это необходимо
для ICMP и SO_MARK. Только сокеты этого процесса и его измерительных дочерних
процессов получают `0x48000000`, включая bypass-бит ZeroBlock `0x40000000`.
При невозможности выставить метку измерение завершается ошибкой.

DNS процесса обращается прямо к публичным резолверам, не к локальному DNS proxy.
Пользовательский трафик и правила ZeroBlock не перенастраиваются. Счётчик Probe:
`nft list chain inet fw4 probe_direct_counter`. Настройка сохраняется в
`/etc/nftables.d/90-roskompozor-probe.nft` и проверяется `fw4 check`.
Если в старой конфигурации задан `api_connect_ip` — частный IPv4 собственного
сервера, применяется DNAT только помеченного трафика Probe к API/контролю
на адресе сервиса. Произвольные цели по-прежнему ограничены публичными IP.

## Управление и проверки

```sh
systemctl status roskompozor-probe-next
journalctl -u roskompozor-probe-next -n 30
# OpenWrt:
/etc/init.d/roskompozor-probe-next status
logread -e roskompozor-probe-next
# Тесты из дерева исходников:
python3 -m unittest discover -s next -p 'test_*.py' -v
python3 build_installer.py
```

Режим `shadow` остаётся для отдельных испытаний; действующие установки работают
в `mode: api`. Каждому узлу нужен собственный ключ. После смены когорты старые
ключи отозваны на сервере, а завершённая история остаётся доступной.

Пока не реализованы traceroute, локализация DPI и QUIC. Метки маршрутизации
проверены на ZeroBlock 0.8.5-r121 и OpenWrt/RouteRich 24.10.6.
